# 永久環境改版前的唯讀經濟基準

`worker/tools/realm-economy-baseline.mjs` 產生可審查的聚合查詢，供 POE 掛機版平衡前確認玩家已累積的進度與投入。這份工具不代表已取得正式環境資料，也不代表完成正式機版本核對。

## 執行方式

使用 Node 24，先按根目錄 `AGENTS.md` 安裝既有依賴。預設只輸出 SQL，不連線、不初始化資料庫、不執行 migration。

```sh
node worker/tools/realm-economy-baseline.mjs --as-of 2026-11-01T00:00:00Z
```

隔離本機 D1 已有完整結構及測試資料時，可以明確指定本機執行。

```sh
node worker/tools/realm-economy-baseline.mjs --local --database DB --persist-to /tmp/realm-baseline-local --output /tmp/realm-baseline-local.json
```

正式查詢必須同時給 `--remote` 與明確資料庫名稱或 binding，並使用已配置且具備 D1 查詢權限的 Wrangler 憑證。程式固定非互動執行，不呼叫登入指令、不搜尋或匯出秘密、不自動取得額外權限。沒有有效憑證、資料庫綁定不符或結構缺漏時直接失敗，不輸出不完整結果。

```sh
node worker/tools/realm-economy-baseline.mjs --remote --database elf-rpg --as-of 2026-11-01T00:00:00Z --output /tmp/realm-baseline-production.json
```

先審查預設輸出的 SQL，再由已獲授權的維護環境執行正式查詢。工具僅執行內建的 `SELECT`／唯讀 CTE；沒有自訂 SQL 入口。它不會調整角色、裝備、強化、帳本、賽季狀態或玩家進度。執行時固定使用 Wrangler `--command` 查詢介面；**不可改成 `--remote --file`，後者走 D1 匯入流程，可能暫停服務且不回傳各個 SELECT 的資料列。** `--output` 必須位於 Git 儲存庫之外，而且不覆寫已有檔案；成功的 SQL／JSON 檔案權限為 `0600`。暫存 Wrangler 執行日誌會在結束後清除。

## 匯出內容與解讀

| 區段 | 內容 | 判讀限制 |
| --- | --- | --- |
| 人口與職業等級 | 現存帳號、角色、已封存角色數；目前選角；職業／分支／十級區間；近七天結算與帳本活動 | 自動掛機也會產生活動，不能當作玩家登入人數。 |
| 金幣分布 | 全部現存角色與目前選角各自的總量、平均、最小最大與 P10／25／50／75／90／99 | 採 nearest-rank 分位數；不把帳號分身誤當同時生產角色。託管金幣另列。 |
| 裝備 | 職業、T 階、稀有度、遺物等級、每個 `enhance_level` 數量、穿戴／綁定／託管數 | 稀有度沿用 `gearRaritySql`，包含舊遺物與星環裝備的最低稀有度規則。每件裝備的 +N 完全不改。 |
| 背包與帳本 | 背包材料總量；預設七天內各活動的金幣、道具流入／流出與經驗淨額 | 交易、撤回、託管屬資產移動，不能全部當成新產出或銷毀。裝備／天使實例編號先合併成類別，不匯出 ID。 |
| 掛機 | 結算分鐘、跳過分鐘、角色小時、金幣毛收益、經驗得失、擊殺、死亡、升級及每小時比率 | 分母是已解析的角色分鐘，不是玩家在線小時；金幣為毛收益，不能當成扣除所有成本後的淨收益。 |
| 消耗品 | 紅藍水各階消耗、其他消耗品，以及每個已解析角色小時的使用量 | 道具可能來自免費獎勵，實際購買支出以帳本為準。 |
| 進度 | 目前地圖、待轉職階段、最高塔層、累計死亡；近七天建立的短隊與星環遠征狀態／已完成階段 | 活動仍進行中時不能用「已完成／全部」當作最終通關率；新 POE 星圖尚未上線時沒有正式星圖基準。 |
| 託管 | 雙人交易鎖定金幣、交易所各類資產數量 | 掛單標價不是現有金幣供給，不會加到錢包總量。 |

`--as-of` 固定帳本及結算紀錄的統計上限，預設最近七天，可用 `--days 1..90` 調整。**角色餘額、裝備與選角仍是各查詢執行當下的現況，不是指定日期的歷史還原。** 整份匯出不是停服快照；正式機持續運作時，各區段之間可能發生新的交易或結算。

掛機區段依「結算紀錄建立時間」選取，並要求 `to_at` 不超過截止時間。離線補算可能涵蓋七天之前的遊戲時間，因此另附最早 `from_at`／最晚 `to_at` 與解析分鐘。報表按角色目前職業及等級分類，舊紀錄沒有完整歷史配置快照，不能據此斷言某個流派的因果強弱。改版平衡仍需用隔離模型和代表配置重播驗證。

輸出只有彙總數據；不包含玩家名稱、Telegram ID、角色 ID、裝備實例 ID、群組訊息、帳本備註或任何憑證。小樣本類別會保留樣本數，避免把少量結果解讀成普遍現象。這一期未匯出匿名角色戰力樣本。

## 驗證與資料保留

`worker/test/realm-economy-baseline.test.js` 以真 SQLite 結構執行全部查詢，核對分位數、結算收益、藥水使用、裝備強化分布及識別資料不外流，並逐表比較前後內容完全一致。這是隔離資料驗證，不是正式機查詢收據。

拿到正式聚合數據後，應先比較改版前後各職業／等級的收益、存活、消耗與完成時間，再決定數值調整；不得以重新 seed、刪角、重設裝備 +N 或回寫強化歷史來消除差距。正式環境存取、SQL 執行與任何日後 migration 都是不同步驟。

Cloudflare 執行介面參考：[Wrangler D1 commands](https://developers.cloudflare.com/d1/wrangler-commands/)。工具使用根目錄鎖定的 Wrangler，沒有直接呼叫遊戲結算 API。
