三、收據、防重與交易界線

四類操作保存原 request ID、完整 canonical signature、typed result 與實際 costs，並核對原 creation/operation/purchase/cosmetic authority。ready=false、tactic、party、offer、nullable cosmetic 及操作種類均屬原操作內容；同ID換內容或跨kind不能重用。App/Service namespace 各自隔離。

Version 1 receipt 與最後原 authority 寫入同一 batch；每個實際寫入 batch 都重新檢查目前帳號/角色。收據查詢不補發、不重建破損資料。缺版本、空結果、原 authority 不吻合或 debit ledger 缺漏，都不冒充成功。原隨機裝備直接恢復 purchase.reward_json 和原裝備ID，出售或換職也不重新抽取。已擁有星紋的新重複購買依原規則 alreadyOwned:true、costs:{}，沒有虛構第二筆扣款。

整個原操作並非一筆全域交易。原 sweep/advance、begin逐隊員的withPlayer準備/閒置結算可能先各自合法提交；新收據只證明最後 authority batch。切角之後 guard 擋住後續寫入，但不回滾之前合法完成的 checkpoint。缺最後收據不能推出所有前置工作零寫入。原階段(run_id,char_id,stage)防重仍是結算權威。

前端 pending 保留原 ID/body，依 account/realm/character 隔離，並用 epoch、角色revision floor及party rev擋舊回覆。not_found 保留待核對狀態；查詢、取消、重整、重開均不重送。只有有效 recoveryAllowed 與明確確認，才用同一ID/body重試；成功匹配或明確核對完整收據才解除。
