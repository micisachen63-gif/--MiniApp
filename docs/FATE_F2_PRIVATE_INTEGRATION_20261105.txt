二、權威、交易與失聯處理

新增五個 POST 路由：
- fate/private/scene：私人摘要與 domain 投影，SELECT-only。
- fate/private/profile：owner 明確查閱檔案，SELECT-only。
- fate/private/receipt：以原 intent／ID 查原結果，SELECT-only。
- fate/private/action-scoped：保存／刪除、生日啟程與每日同步。
- fate/private/cancel：符合契約的未成立原操作，以原 ID 明確封存。

讀取雖使用 POST，沒有生成 profile／daily、補結果或重送的副作用。寫入捕捉帳號／realm／角色與 expected domain，在原主 batch 核對 guard、執行原 operation 並寫 typed receipt。profile／daily SQL CAS 加上 append-only operations 的 generation，能辨識同毫秒 erase／recreate，避免舊畫面的確認作用於新一代資料。原 Fate.start 的 preflight 與主 batch 仍保留原有分段邊界，不宣稱整個 HTTP request 只有一個交易。

private:* namespace 使用僅伺服器持有的 Symbol capability，JSON 無法偽造。start 的保留 namespace 檢查在原 preflight 前執行。原本可經 legacy 入口碰到私人 envelope 的五個 regression 先保留 red，再修至全部通過。

收據須符合原 operation、typed ledger、proof、scope、結果與成本。單獨 operation、單獨 ledger 或矛盾資料不授權重做／取消，也不以新 ID「修復」未知結果。失聯保留原 ID；沒有私人記憶體時不能重送 save，只能依原 lookup 契約明確結束未決請求。取消形成原 ID 的 cancelled receipt。

三、隱私與前端行為

瀏覽器私人輸入保存在記憶體；可持久的 pending 僅保留公開 scope、ID、nonce 與 expected metadata。生日／星盤／旅箋內容及內部 payloadHash 不進一般 pending、公開 receipt、公開 ledger 投影或持久 QA 明文。測試證據以嚴格欄位白名單及程序內祕密 HMAC 比對整個 DB，不保留可還原資料庫。畫面以動態私人區塊與表單遮罩保存，未啟用含私人內容的 trace。

F1 與 F2 互鎖 pending，包括毀損 pending。角色、帳號或 realm 改變時立即清除私人輸入；舊 scope 的晚回應不能污染目前角色。編輯／composition 期間延後 private repaint，父層 F1 更新保留已連接的私人 subtree，失去焦點後恢復讀取。實際 browser 發現自訂出生地切換會收合原生 details，已用最小修正保留該節點 open 狀態並加入 regression；明確清除、scope 改變與 erase 仍立即清理。
