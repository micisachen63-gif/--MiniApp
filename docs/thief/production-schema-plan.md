# 盜賊保留資料的職業限制擴充

使用者已明確授權：「同意，驗證通過後執行並發布」。核准範圍是三處職業 CHECK，以及天使外鍵依賴閉包共七張表。尚未執行正式變更。

隔離 D1 已從真實完整備份成功還原；41 張業務表的每一列 rowid、SQLite 型別與所有欄位位元組、sqlite_sequence 均逐頁雜湊比對一致。三個 DROP／restore／verify 階段故障注入全部回滾，七張受影響表與135個結構物件完全復原。最後165個陳述在單次 D1 batch 執行1971ms，41表完整比對通過。證據見 hosted-d1-rehearsal.json。所有玩家原始資料僅在忽略的 .release-sync 及隔離 D1，沒有進 Git。

執行前需完成角色／裝備／技能驗收與完整測試，將確切來源推送合併 GitHub main；重新讀取正式 schema，要求與 structured JSON candidate 完全相同，再取得新完整備份、還原驗證與 Time Travel 書籤。

短暫維護採 D1 單次原子 batch 的資料庫寫入鎖。所有快照、葉節點優先 DROP、父節點優先重建與還原、型別與位元組守衛、FK及結構守衛皆在同一交易；其他 DB 查詢由 D1 排序，不會讀到半套表，也不會在快照與還原之間寫入。舊三職業的欄位、主鍵、外鍵、索引與觸發器維持相同介面，排隊中的舊版請求可在交易結束後繼續執行。沒有宣稱已停止遊戲、BOT、DO 或 cron。不可把165個正式陳述拆成不同請求。

執行器是獨立、短期、密鑰保護的 Worker，只接受固定 candidate，不接受任意 SQL。正式模式僅有 /schema 和 /apply；不得在正式庫做故障注入或備份還原測試。它必須核對核准標記、正式 DB ID、已驗證的隔離排練證據、已合併的來源 commit，以及變更前135個結構物件。請求結果不確定時只查結構與版本，禁止盲目重送。

正式擴充成功後需核對預期 schema hash、FK與quick_check，再完成 migration tracking／開放閘門與完整測試；遊戲及BOT依根目錄受鎖發布流程部署，只能由乾淨且等於 origin/main 的來源發布。來源、正式版本與健康驗證全部成功才回報同步。完成後清理臨時執行器、隔離 D1及純傳輸用分支，保留私有備份及無玩家資料的收據。
