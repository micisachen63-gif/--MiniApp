五、仍需另一期處理的玩法／平衡缺口
1. 盜賊三、四轉缺少數值專精與獨有機制；現有前三職業的 advanced-specializations.js 尚未接盜賊。
   接手時同時檢查 thief-data.js、stats.js 的盜賊特例、classes.js 與成長樹 metadata，避免只改預覽。
   每對兄弟分支須有真實戰鬥差異，並測掛機、PK、群王、組隊；不要僅憑名稱或動畫判定完成。
2. 新增90／120級特殊技能書尚未製作；目前繼承六本30／40／60級技能，不是取得路徑故障。
3. 同等級標準裝備的簡化 EHP 模型，盜賊在120級所有對照中最高只有他職約49.44%。
   此模型未納入煙幕、盾、吸血、敵人機制及實際戰鬥長度；不能據此宣稱實際PK勝率或直接調平衡。
   建議下一階段用固定種子與同預算裝備，比較持續輸出、耗魔、存活及副本貢獻後調整。
4. 組隊副本的標記可供同場隊友使用；群組BOSS的 bossCombat 狀態目前各角色獨立保存。
   若要群王全體玩家共享破綻／削弱，需額外設計共用首領狀態、期限與競爭更新，現況不能宣稱已支援。
5. 後期職業搭配副本與資源累積／手動戰技仍屬未上線規劃；勿直接合併歷史 party-role-mechanics 草稿。

六、接手與協作
先讀根目錄 AGENTS.md、AI_HANDOVER.md，fetch origin/main。
人物視窗仍在製作成長樹頁面；本次不動其 worktree、人物圖、動畫、成長樹或未提交檔案。
修正必須先正常提交／同步 GitHub，再從乾淨且等於 main 的提交執行根目錄 npm run deploy:worker。
只變更遊戲服務，無需重發 BOT。用共用發布鎖及最新正式收據防止覆蓋其他視窗的合法新版。
發布不明時先唯讀核對，不可重試覆蓋。驗證工具如遇換行差異，先比對原始收據與 LF／CRLF，勿判定為遊戲功能損毀。
完整首次上線證據仍保留 docs/thief/release-validation.json；候選期 combat-readiness 等檔案的 false 不代表正式職業被停用。
