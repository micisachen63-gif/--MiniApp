三、共用浮窗與草稿

新增 scene-window-manager.js。五個主入口固定在底部，開啟後沿用同一個 dialog，戰鬥場景仍可見。預設透明面板另提供「易讀模式」提高文字與面板對比。

返回先處理模組內的確認或選裝，再回上一層；Escape 與 Telegram BackButton 接相同返回行為。焦點限制在浮窗與五入口之內，關閉後回到原先入口。手機 390×844 與桌面 1280×900 都驗證面板、導覽及捲動範圍。

同帳號／世界／角色／epoch 的各頁草稿保存篩選、數量、選取、捲動及表單。Atlas 保存實際構築、分鐘與紅藍水、銘刻選擇、天賦節點／縮放／畫布位置。兩套收藏保存模式、來源、階級、完成狀態、頁碼、picker 與選裝。

角色或世界切換會清除一般表單及選取，導覽版本票據也處理 A→B→A、關閉後重開及晚到回覆，避免舊內容覆蓋新角色。

繁中搜尋在 compositionstart 至 compositionend 期間保留原輸入 DOM；背景資料可接收，整體重畫延後到組字結束。背包勾選以精確 item ID 恢復焦點，清除舊捲動 observer，避免背景更新把捲動位置拉回先前值。

收藏保留原本出征鎖定：進行中的 Atlas 不可典藏／精煉裝備。被阻擋的指定裝備不會被改選或消耗；返營後明確再次進入會重新核對。成功預選後，使用者自行取消或改選的草稿仍保留。

四、工坊收據與未知結果

新增純查詢：
POST /app/api/forge/receipt
POST /rpg/forge/receipt

兩個路由都要求明確 X-Realm-Id。Mini App 使用已驗證帳號的目前角色與 app namespace；內部服務路由固定 service namespace，驗證帳號與目前角色所有權。客戶端不能以 namespace、tgId 或另一角色 ID 代替授權。

查詢以完整事件 ID 精確取得強化／洗鍊主帳務，以及同次自動補購卷軸紀錄，不受最近 15 筆帳本限制。只有主事件存在才回 found:true；只有補購紀錄不代表完整操作已完成。裝備已破碎或刪除仍可讀原帳務。查詢只有 SELECT，不結算、不補發、不 recordBehavior，凍結世界仍可讀既有紀錄。

一般強化／洗鍊回覆遺失時，只查原 receipt，不再次送出操作。查不到紀錄保留待確認狀態，不能把 found:false 解讀為操作一定沒發生。

各操作依實際服務能力處理：
- 手動強化／洗鍊：原事件純查詢。
- 自動洗鍊 start：已有完整 requestId 與設定重播契約，使用原內容核對。
- 自動強化 start／stop：讀狀態核對原作業，不重新開工。
- 買物／裝備／寶箱：沿原購買 ID 的既有防重，再讀回現況。
- settings／refill：讀回核對，不自動重送。
- 背包穿脫／出售／一般開箱：未知結果只讀回並由使用者結束核對；Fate gift 僅沿其真實收據契約處理。

背包待確認紀錄依 account／realm／character 保存，不含 epoch，使用 sessionStorage 與記憶體 fallback；普通草稿仍依外殼 context 隔離。共用紀錄與清除標記避免舊 route 讓已清除操作復活，每筆識別與 current/dispose 檢查避免舊回覆清掉新 pending。工坊與收藏亦保留原待確認紀錄。

五、真實背景行為與讀取

原有 me／shop 會經 withPlayer 進行既有結算，不能宣稱為純讀；本批不新增它們的高頻輪詢。背包先完整等待 me 及其場景刷新，再並行純狀態讀取。只有同一有效 context 的 atlas/status 遭 stale_response 時做一次有界重讀，真正連線失敗仍顯示提示。

Atlas 一般 running snapshot 只更新既有進度與補給文字，不重建輸入、不呼叫 me。狀態轉換需要的 status 查詢合併與去重；暫時失敗可由下一個健康快照再同步。configure／start／craft 成功但隨後讀取失敗時，保留剛送出的欄位，直到讀到新狀態再清理；等待期間的新編輯受到保護。

工坊只在有執行中作業且可見時，以約 8 秒更新純狀態；結束時讀回一次最新裝備。本機 preview 使用現有 AutoEnhance／AutoReroll sweep/step 服務及原 next_at／3 秒間隔驅動合成作業，沒有前端假造結果。正式排程服務未更動。
