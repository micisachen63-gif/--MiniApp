2026-10-20 原隊連刷共用群組戰報

行為
打寶／爬塔以「原隊再戰一場」續開時，沿用第一則群組圖卡，標示「第 N 場」，同步更新圖片／GIF、進度、領獎／戰術回呼與遊戲連結。缺人補招仍屬同一隊。手動重新建立隊伍才另發圖卡、場次從 1 計。
既有隊伍下一次續開會沿用當前隊伍既有的群組訊息；已經產生的歷史多則訊息不刪除，不修改舊獎勵。

資料與競爭
每場依然使用自己的 party ID、戰鬥、操作及獎勵收據。新增 JSON 通知中繼資料 cardRootId／cardRun 與根場次 cardLatestId，無 schema migration。續開的 CAS 交易同時提交根通知最新指標，失敗全部回滾。
通知 hydration 與 TG「更新進度」查詢最新場次，個人戰報／舊領獎仍依原場次查詢。群訊息 ID 寫回第一場及送出場，原訊息較晚回報也不讓續開重貼。
BOT 以根通知 ID 序列化與持久排隊，按（場次，該場 rev）比較：新場 rev 從 0 開始仍可更新，延遲舊場不能蓋回新場。GIF 延遲更新不得覆蓋已排隊的新場；重啟會恢復 dirty map／訊息位址。明確失敗可降成編輯原 caption；不確定編輯不另發訊息，缺失訊息不自動重貼洗頻。

驗證
新增 Worker 3 項跨服務隔離整合：三場真實自動戰鬥、同一訊息、BOT 重啟、新 callback／deep link、九份獨立入袋收據與每人 24 碎片；晚到訊息位址／舊 outbox 更新最新場；併發續開一份後繼、失敗回滾不移通知指標。
新增 BOT 5 項：較低 rev 新場、延遲舊場、高度重疊編輯與持久佇列、GIF defer 競爭、只有伺服器位址的恢復、已完成 dirty 清理、遺失／不確定編輯不重貼。全部使用假 Telegram transport，沒有發測試訊息給真群組或真玩家。
根目錄 npm test 涵蓋所有 Worker／BOT 測試；隔離結果在忽略的 .release-sync/party-card-*。

發布
先 BOT（相容舊 Worker 無通知中繼資料），再 Worker。兩者皆走 PR／必要 CI、乾淨 main 根目錄發布與 deployment-records 收據。無資料庫遷移、不改怪物／戰力／掉落／經濟／每日次數，不推進正式玩家做驗收。發布狀態以收據及即時 runtime 為準。
