一、整合結果

本批補齊 Atlas 與原版喝水設定之間的接線。新出征可攜帶原有紅水一至四階、藍水一至四階，每色合計最多 500 瓶。出發時逐物品原子預留，實際使用時保留階級身分，結束、死亡或停止後把未使用數量歸還原種類。沒有新增藥水、修改藥水效果或價格，也沒有新增 migration。

新出征把角色已保存的設定與藥水效果、價格保存為當趟快照。紅水在生命嚴格低於已保存門檻時使用；藍水依原版規則，開啟後在低於或等於門檻、或實際技能魔力不足時嘗試補水。關閉自動藍水後，門檻補水和技能救急皆不使用藍水。自動選擇依最低階有庫存者先喝；指定種類耗盡後不替代成其他階。當趟修改原版設定不會回頭改寫已出發快照，下一趟才套用。

使用獨立補給版本 atlas-supplies-v1，不更動 atlas-v1 至 atlas-v4 的內容與掉落版本。舊存檔完全缺少補給版本時保持原有初階藥水、40% 紅水門檻與原策略補藍流程；不會在中途套用新設定。未知版本、不完整快照或逐項餘額不守恆會拒絕結算。

1. 新 start 請求：supplies.items 只接受 red_1..red_4、blue_1..blue_4 的非負整數；禁止混入舊 hp/mp、未知種類或客戶端 policy。每種顏色總數不可超過 500；庫存於真正交易內重新核對。
2. 舊 start 請求：supplies.hp/mp 仍代表 red_1/blue_1。既有 hpRestore/mpRestore 提示繼續忽略，保留原有 request signature，讓升級前成功但遺失回覆的請求仍能取得原收據。
3. status.supplies 與 scene.live.supplies 的 hp/mp 保留初階藥水原義；新增 totals 表示各色全階合計，items 表示八種庫存，policy 表示下趟設定。這保護仍快取舊版 atlas-ui 的客戶端。
4. run.supplies 的 hp/mp 是當趟各色總量，並提供 items、initialItems、usedItems、policy 與 supplyRulesVersion。資料只反映已提交的狀態，讀 status 不推進戰鬥。
5. 預留、歸還、角色和出征 revision、活動、獎勵與帳務沿用同一交易；同 request、競爭請求及 commit 成功後回覆遺失皆不得重複扣還。
6. 成本校準工具對新版以 usedItems × priceByItem 計算；舊版自訂單價公式保留。這是本機診斷，不是改變玩家收入或物品售價。
